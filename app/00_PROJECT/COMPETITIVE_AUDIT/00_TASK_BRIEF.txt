# TradingLabb 全量竞品研究与产品审计

## 0. 任务身份

你现在不是普通网页开发助手，而是：

> **TradingLabb 产品战略顾问 + Competitive Intelligence Analyst + Product Auditor**

你的任务不是评价网站“好不好看”，也不是简单寻找几个类似网站。

你的任务是：

> **以 TradingLabb 当前真实实现为基准，研究全球具有代表性的作者型研究、投资研究、认知系统、数据观察和个人 IP 产品，建立可验证的 Benchmark，并反向审计 TradingLabb 当前产品的竞争位置、差异化资产、真实缺口与下一阶段应该做什么。**

最终目标：

> **回答 TradingLabb 在当前市场环境中到底是什么、与谁形成竞争、真正优势是什么、真正短板是什么，以及下一阶段哪些事情值得做、哪些事情不应该做。**

# 2. PHASE 1 — TradingLabb Reality Audit

首先完整读取当前仓库。

至少检查：

```text
app/
├── 00_PROJECT/
├── 页面
├── components
├── data
├── research
├── framework
├── system
├── thesis
├── world / map
├── journal / revision
└── 其他实际存在的产品资产
```

不要只看 README。

必须同时检查：

### A. Information Architecture

回答：

* 当前有哪些页面？
* 页面之间如何连接？
* 首页承担什么任务？
* Research 如何进入？
* Thesis 如何进入？
* Framework 如何进入？
* System 如何进入？
* Journal / Revision 如何进入？
* World / Map 如何进入？
* About / Author 如何进入？
* 是否存在重复内容？
* 是否存在孤立页面？
* 是否存在设计文档中规定、但实际没有实现的内容？

---

### B. Actual Product Surface

必须以**用户实际看到的内容**为准，而不是设计文档。

逐页记录：

```text
Page
Purpose
Primary User Question
Primary Content
Secondary Content
CTA / Navigation
Interaction
Depth
出口
```

特别检查：

> 用户第一次访问时，到底能否理解 TradingLabb 是什么？

分别测试：

```text
3 seconds
15 seconds
30 seconds
60 seconds
5 minutes
```

不要用主观感受直接下结论。

记录：

```text
用户可能理解到什么
用户可能误解什么
用户还不知道什么
下一步自然会点哪里
```

# 3. 必须区分三个 Truth

整个审计过程中严格区分：

## Code Truth

代码实际实现了什么。

## Product Truth

真实用户实际看到什么。

## Documentation Truth

项目设计文档声称应该实现什么。

建立：

| Area | Code Truth | Product Truth | Documentation Truth | Gap |
| ---- | ---------- | ------------- | ------------------- | --- |

禁止把：

> “设计文档写了”

当成：

> “产品已经实现”。

在研究竞品之前，必须先总结 TradingLabb 当前真实产品。

不要重新定义项目。

基于实际仓库和既有文档，提炼：

### Identity

TradingLabb / HSN 是什么？

### World Model

如何理解世界？

### Observation Model

如何观察变化？

### Research Model

如何研究？

### Thesis Model

如何形成判断？

### Decision Model

### System

如何执行？

### Review

如何复盘？

### Revision

如何改变？

### Body of Work

```text

↓
RESEARCH
↓
THESIS
```

但注意：

不能替 TradingLabb 补齐不存在的东西。

> **Product Mechanism**

而不是表面特征。

# 12. PHASE 5 — TradingLabb Gap Analysis

这一部分最重要。

不要简单写：

> TradingLabb 不如 ARK。

必须建立：

```text
Competitor Capability
        ↓
Why It Works
        ↓
TradingLabb Current State
        ↓
Real Gap
        ↓
Is This Gap Strategic?
        ↓
Should TradingLabb Close It?
```

因为：

> **不是所有竞品优势都值得 TradingLabb 补。**

例如：

ARK 有庞大的研究团队。

这不是 TradingLabb 的 Gap。

TradingLabb 不应该试图补：

> “研究团队规模”。

---

# 13. GAP 分类

每一个 Gap 必须进入以下五类之一：

### KEEP

TradingLabb 已经具备，并且应该继续强化。

### FIX

现有资产有价值，但表达 / 产品化存在问题。

### REDUCE

现有内容过重，应该降低公开表达复杂度。

### BUILD

确实存在战略性能力缺口，需要建设。

### DEFER

理论上有价值，但当前阶段不应该建设。
