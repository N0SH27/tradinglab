## 0. 三站设计基因（一句话各自质感的来源）

| | 基因 | 质感来源（证据） |
| --- | --- | --- |
| **lizheng.ai** | 编辑级个人品牌页 | 深绿→米白「banding」分节；Noto Serif SC 巨型衬线标题 + Cutout 人像；数据计数带与名人评价墙；195 个动效元素的滚动编排；hover 微反馈无处不在 |
| **ashton.is** | 单时刻手工艺动效 | 整站动效预算几乎全花在一个 6.6s 循环的名字卷轴动画上（`@property --roll/--f` + 百分点级 keyframe 时间轴 + 分段缓动 + 完整 reduced-motion 降级）；其余极简（43 个动效元素、151KB）；Poppins 800 巨标题 vs Inter 小正文的极端字阶对比 |
| **TradingLabb** | 纸上档案 | 纸白底 + 发丝线分节 + 朱砂/水蓝两点墨色；Noto Serif SC 大标题；IO 触发的 900ms 淡入 reveal（一次性）；太极旋转、水墨光标、墨色转场；64 个动效元素；路由分包与自研 ink 引擎 |

## 1. 动效

### 1.1 动效语法清单（代码事实）

| 语法 | TradingLabb | lizheng.ai | ashton.is |
| --- | --- | --- | --- |
| 入场（scroll reveal） | ✅ data-reveal：opacity+transform 900ms ease，一次性（`useReveal.ts`） | ✅ lz-rise / lz-rise-portrait / lz-mark-in 自定义 keyframes | ❌ 几乎不用 |
| hover 反馈 | ⚠️ 仅 `ink-hv` 颜色微变 | ✅ 丰富：卡片 `-translate-y-0.5/-1`、图片 `scale-110`、`opacity-90/95`、按钮阴影 | ✅ 作品卡 hover 状态 |
| 签名时刻（hero 主动画） | ❌ 无（太极仪是常驻旋转，非入场编排） | ✅ 巨标+人像 mark-in | ✅ 名字卷轴 6.6s 循环 |
| 持续氛围动效 | taiji-spin、水墨光标 | lz-live-dot、shimmer、marquee | 无 |
| 页面转场 | ✅ InkTransition（墨色晕染） | SPA 默认 | 无 |
| 缓动性格 | 5 条曲线并存，reveal 用纯 ease | 主导 `(.2,.7,.2,1)`（8 处），全站一个「浮起」性格 | 分段手工缓动 `.25,.7,.2,1` / `.3,0,.2,1` / `.5,0,.3,1`，一个动作有起承转合 |
| reduced-motion | ✅ 已处理（ink 引擎四件套全部降级） | 未检出 | ✅ 完整降级（静态全名） |
| 动效元素密度 | 64（5512px）≈ 11.6/千 px | 195（8841px）≈ 22/千 px | 43（2601px）≈ 16.5/千 px |

### 1.2 差距（按质感贡献排序）

1. **hover 反馈层缺失是最大落差。** lizheng 的每个可点元素都有「被触碰」的回应；TradingLabb 只有颜色变浅。对「纸」的隐喻，这等于**纸没有肌理**。
2. **没有签名时刻。** 两站首屏都有一个「只有这里有的动作」；TradingLabb 最贵的屏幕用了全站最普通的语法。
3. **reveal 缓动无性格**（纯 ease 是浏览器默认值，不是设计决定）。

## 3. 布局

| 维度 | TradingLabb | lizheng.ai | ashton.is |
| --- | --- | --- | --- |
| 分节机制 | 发丝线 + 纸白一色到底 | 深绿/米白 banding 反色带 | 大留白分区 |
| 长页节奏 | 5512px，节距均等（py-20/24/28） | 8841px，密度变化大 | 2601px 单屏 |
| 页脚 | 归档树（11 列知识树）+ 印章 + 座右铭 | 多栏链接 | 巨字导航 + 联系 |

**差距：乐句单一**——全页同一音色读到底没有换气。lizheng 用 banding 换气，但**不建议学 banding**（摧毁纸白一体）；TradingLabb 库里已有更好的材质：`bg-ivory` 宣纸底（END 区已用）+ 朱砂印章，应发展为「册页」段落记号。另：首页 Research 卡区是唯一无眉题的主要节段。

## 4. 响应式与移动端（新增）

三站 375px 首屏实测（`ref-sites/*-mobile.png`）：

| | TradingLabb | lizheng.ai | ashton.is |
| --- | --- | --- | --- |
| 字阶适配 | ✅ clamp 平滑缩放，宣言仍具冲击力 | ✅ 人像优先重排（头像→大字→正文），阅读顺序重排得当 | ✅ 名字标记者居中独存，品牌时刻存活 |
| 导航适配 | ✅ 抽屉菜单（全部 15 个目的地可达） | ✅ 汉堡菜单 + EN 切换保留 | 单页无此问题 |
| 发现的问题 | ⚠️ 首屏左上角有孤立墨点残影（约 15,15px）——代码有 `pointer: fine` 守卫（`InkCursor.tsx:20`），疑似组件在守卫生效前渲染了一帧；需排查 | 首屏 1MB+（人像照片），弱网体验风险 | 上半屏大面积留白（动画节拍所致，可接受但偏空） |
| 内容重排 | hero 四行小字断行自然；「玄之又玄」居中保留 | 履历时间轴转纵向 | — |

**移动端结论**：TradingLabb 响应式是三站中结构最稳的（字阶、抽屉、密度都成立），唯二待办是墨点残影排查与 Flip 卡在触屏上的翻转交互确认（hover 语义在触屏的替代方案是否已覆盖，本轮未逐页验证）。

## 5. 性能与工程质感（新增）

| | TradingLabb（生产） | lizheng.ai | ashton.is |
| --- | --- | --- | --- |
| 首屏体积 | 主包 232KB + 首页分包 28KB + CSS 34KB ≈ **294KB（不含字体）** | **2006KB** / 52 请求 | **151KB** / 12 请求 |
| JS 架构 | ✅ 路由级分包 + 自研 ink 引擎（零依赖动效） | React SPA 单包 897KB（未分包或分包少） | 原生手写 JS，零框架 |
| 字体策略 | ⚠️ **Google Fonts CDN**（Noto Serif SC 900/700/600/400 + Sans SC 四档 + Plex Mono，CJK 切片按需加载） | 自托管 woff2（Geist Variable 分 unicode-range 子集） | 自托管子集化 |
| 体积风险源 | CJK 衬线 900 字重切片是最大变量（单页实载通常 300–800KB，未实测）；Google CDN 有两处隐性成本：① 访客 IP 暴露给 Google（隐私）② 大陆网络可达性不稳定 | 人像/照片 | 几乎无 |

**判断**：TradingLabb 的工程底座是三站中最好的（分包、自研引擎、CSS 变量体系）——**唯一短板是字体交付策略**。ashton 证明了一个内容站可以把首屏压到 151KB 且质感不减；TradingLabb 不需要做到 151KB（内容型长站 + CJK 衬线是刚需），但「自托管 + 按页面用到的字重子集化」可以把字体从「外部变量」变成「可控资产」，同时解决隐私与大陆可用性。

## 6. 交互架构与导航（新增）

| | TradingLabb | lizheng.ai | ashton.is |

| | TradingLabb | lizheng.ai | ashton.is |

| 符号系统 | 太极/阴阳/朱砂/水蓝/印章/洞箫（多符号） | 深绿 + 「立正」字标（双符号） | 角框 + 名字（单符号） |

## 10. 改进建议汇总（贴合水墨/档案风格，按优先级）

> 纪律：所有建议必须能用现有设计语言（纸/墨/朱砂/发丝线）表达，不引入新风格、不引入动效库。

| 优先级 | 项 | 维度 | 说明 |
| --- | --- | --- | --- |
| **P0** | hover 反馈层「纸上肌理」 | 动效 | 行级墨色渗入 + 卡级上浮 2px/边框加深，200ms；质感差距最大、成本最低（约半天） |
| **P0** | 首屏「落墨」签名时刻 | 动效/品牌 | 两行标题分行浮起、朱砂句号最后落下（≤1.2s 一次）；最贵的屏幕不该用最普通的语法 |
| **P1** | 缓动家族化 | 动效 | 收敛为 `--ease-reveal (0.22,0.61,0.36,1)` / `--ease-touch (.2,.7,.2,1)` 两条命名曲线 |
| **P1** | 册页节奏 | 布局 | 每 2–3 节允许一节 `bg-ivory` 宣纸底作段落记号；先在首页试点 What Changed 或 WUWEI 区 |
| **P1** | Research 区眉题 | 布局 | 唯一无眉题的主要节段，补一行 Label |
| **P1** | 字体自托管子集化 | 性能 | 按页面用到的字重自托管 woff2（ashton 151KB 的启示）；解决隐私、大陆可达性、体积三问题 |
| **P1** | 移动端墨点残影排查 | 响应式 | InkCursor 守卫生效前的首帧渲染，加初始 `visibility:hidden` 或惰性挂载即可 |
| **P2** | 数据行排印精修 | 排版 | What Changed 数字组定宽、基线对齐；地图/研报长段落加 serif 次级标题层 |
| **P2** | 印章落款分级 | 品牌 | 声明「印章=落款=断言处」为第一符号；朱砂出现频次写成纪律 |
| **P2** | 太极仪滚动联动（可选实验） | 动效 | taiji-spin 转速与滚动轻耦合；幅度小、reduced-motion 已备，仅在 P0/P1 后评估 |

## 11. 不建议学的（反向边界）

- banding 反色带（lizheng）→ 用「宣纸节」替代；marquee/照片横滚带 → 装饰噪声；粉丝计数带 → 稀释谦逊气质
- 更多循环动画 → ashton 的教训是「一个做到底」，持续动效预算（太极+水墨光标+墨色转场）已满
- 前端框架/动效库 → 三站都没有用 GSAP/Framer；TradingLabb 的自研 ink 引擎是资产不是负债
- 首屏人像/大图策略（lizheng 的 1MB 首屏）→ 与「纸」的材质语义冲突

## 12. 总结

| 维度 | TradingLabb 位置 | 与标杆的差距性质 |
| --- | --- | --- |
| 动效 | 语法单一（只有入场） | 缺 hover 层 + 签名时刻 + 缓动性格 |
| 排版 | 同级 | 两处精修 |
| 布局 | 材质好、乐句单一 | 不进口 banding，用册页节奏 |
| 响应式 | 三站最稳 | 一个残影 bug |
| 性能/工程 | **三站最好** | 仅字体交付策略待收编 |
| 交互架构 | 深度最好、宽度可见性弱 | 桌面端目的地可见性 |
| 内容呈现 | 与定位高度匹配 | 吸收次级标题层 |
| 品牌记忆 | 叙事弧最强 | 缺首幕签名时刻、符号未分级 |
| 无障碍 | 隐藏强项 | 机制已备，清残余 |

> **一句话：TradingLabb 在「系统层」（工程、无障碍、内容纪律、叙事弧）已经超过两个对标站，差距集中在「触感层」（hover 肌理、签名时刻、缓动性格）与「交付层」（字体自托管、移动端残影）。最小代价的最大收益仍是 P0 两项——合计 1–2 天，把「纸上档案」从材质层贯彻到动作层。**
