## A · 当前左侧问题分析

现状（`Home.tsx` SEE 左列）：主句「变化，不是线性的。」下方，三态按钮各自拖带一行解释词（增长 · 采纳 · 扩张 / 过渡 · 反转 · 拐点 / 约束 · 出清 · 收缩）。问题：

1. **三态块自身形成了第二个 UI**：六行文字 + 三个色块，视觉重量逼近阴阳仪本体，Polarity 从「认知控制器」滑向「信息说明卡片」。
2. **错位风险**：三列文字宽度不一（「增长 · 采纳 · 扩张」9 字符 vs 「约束 · 出清 · 收缩」9 字符但渲染不等宽），移动端已出现换行错位（见 R0 验收截图 mobile-see.png：三列 hint 折行高度不一）。
3. **解释冗余**：阴阳仪的 aria-label 已携带完整语义词汇（`META.words`），界面层再写一遍属于重复编码——与设计宪法「重复编码删除」一致。

右侧问题（R0 已实现版本）：音孔继承了 `DOT` 三档孔径（22/28/34px）、`nodeFill()` 半实半空、`valuationRing()` 朱砂/深水蓝外环。结果是：一支东方器物上长了 7 个数据节点——洞箫被拉回数据可视化。

## F · 洞箫本体修改方案

R0 问题：管身为直边梯形 + 直线切口，「像几何图形拼出来的竹管」。本轮允许造型优化，纪律不变（黑 / 灰 / 纸色，禁止木纹 / 3D / 阴影 / 国风装饰）：

1. **管身**：两侧轮廓由直线改为极缓的外凸曲线（二次贝塞尔，中段比两端宽约 6–8%），模拟真实紫竹的微妙锥度与弹性；吹口端依旧略细。
2. **吹口**：顶端由「平切 + U 口」改为**斜切歌口**——管顶一道约 15° 斜切，凹口开在斜面上，两笔成形；这是洞箫最可识别的结构特征，也是「单独看也是一支箫」的关键。
3. **竹节**：保持 2 道，但由对称横弧改为**轻微不对称的双线弧**（一深一浅，间距 3–4 单位），落于音孔间隙不变。
4. **尾部**：平切保留，收束线保留；尾端轮廓加极轻的外张（约 3%），像真实箫尾的竹根端。
5. **音孔位**：7 孔仍严格等参数分布于轴线（孔序 = `SLICE` 不变），但孔心轴线随管身曲线微调（仍共线，只随管宽微调视觉居中）。
6. **64° 主轴不变**；验收标准仍为视觉角度，非 CSS 数值。

**器物验收标准（Human 补充，正式纳入）**：把所有 Topic 名称与交互逻辑隐藏后单独看，它必须首先被识别为一支洞箫，而不是一条带圆节点的斜线。
